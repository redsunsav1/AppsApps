# PartnerBuild — Продуктовая дорожная карта

**Дата:** 11 апреля 2026, статус обновлён 28 октября 2026
**Цель:** усилить позиции PartnerBuild как партнёрского слоя поверх CRM застройщика, постепенно повышать зрелость продукта до уровня, на котором его можно показывать крупным застройщикам и продавать как SaaS.
**Стратегическое позиционирование:** не замена Profitbase, а закрытая партнёрская экосистема с геймификацией, мобильным интерфейсом и прямым каналом связи с риелторами.

## Приоритет 1 — Критично

> Без этого нельзя показывать продукт крупному застройщику или продавать как SaaS.

### 1.1 Юридическая чистота 152-ФЗ
- Согласия на обработку персональных данных при регистрации (галочка + текст)
- Политика конфиденциальности (отдельная страница в приложении и на сайте)
- Договор оферты с риелтором (правила пользования клубом)
- Регистрация оператора ПДн в Роскомнадзоре
- Назначение ответственного за обработку ПДн внутри компании
- Уведомление пользователей при изменении условий

### 1.2 Резервирование БД
- Ежедневные автоматические бэкапы (Amvera уже поддерживает)
- Retention минимум 30 дней
- Регулярная проверка восстановимости (раз в месяц — пробное восстановление в тест)
- Документ на случай инцидента: кто, что, в каком порядке делает при потере данных

### 1.3 Логирование действий
- Аудит-лог админских действий: подтверждение сделки, отзыв сделки, одобрение/отклонение заявки, удаление пользователя, изменение настроек
- Аудит-лог действий риелтора: создание брони, загрузка паспорта, отправка документов
- Хранение: отдельная таблица `audit_log` или append-only файл
- Просмотр: страница в админке с фильтрами по дате, пользователю, типу действия

### 1.4 Двухфакторная авторизация для админов
- Сейчас: вход через Telegram WebApp (один фактор)
- Нужно: код подтверждения по SMS или TOTP при входе в админку
- Альтернатива: отдельный пароль/PIN на админ-раздел сверх Telegram-аутентификации

### 1.5 Мониторинг и алерты
- Health check эндпоинт с деталями (`/api/ping` уже есть, расширить)
- Внешний мониторинг (UptimeRobot, Pingdom или встроенный в Amvera)
- Алерты в Telegram на: падение сервера, недоступность БД, ошибки AmoCRM-синхронизации, аномалии в трафике
- Логирование запросов и времени ответа для ретроспективного анализа

## Приоритет 2 — Важно

> Поднимает продукт на следующий уровень зрелости.

### 2.1 Полноценная аналитика для собственника
- Дашборд с ключевыми метриками: сделки за период, конверсия по этапам воронки, средний чек, выручка
- Динамика по проектам, по партнёрам, по источникам
- Топ риелторов, топ продаваемых юнитов, топ программ ипотеки
- Экспорт отчётов в Excel/PDF
- Отдельный доступ для собственника без полных прав админа

### 2.2 Push-уведомления риелтору
- Через Telegram Bot API (уже частично есть)
- Триггеры: смена статуса брони, подтверждение сделки админом, новая программа ипотеки, новое мероприятие, приглашение на приватное событие, изменение цен на проекте
- Настройки уведомлений в профиле (что присылать, что не присылать)
- Дайджест раз в неделю (топ-проекты, новости, ваши результаты)

### 2.3 Документы внутри приложения
- Защищённое хранилище для паспортов, договоров, актов
- Шифрование на уровне БД или объектного хранилища
- Доступ только у владельца документа и админа
- История загрузок с timestamp и hash для верификации
- Удаление по запросу пользователя (152-ФЗ)

### 2.4 Эквайринг бронирования
- Интеграция с ЮKassa, Тинькофф или CloudPayments
- Формальная оплата 5 000 ₽ за бронь — резко повышает серьёзность
- Возврат при отмене брони
- Чек по 54-ФЗ
- Учёт оплат в админке

### 2.5 Web-версия для админа
- Десктопный интерфейс для админ-панели (Telegram WebApp плохо подходит для длительной работы)
- Адаптивная вёрстка под десктоп: широкие таблицы, фильтры, быстрый поиск
- Авторизация через тот же Telegram, но с дополнительной защитой (см. 1.4)
- Поддержка работы с клавиатуры, hotkeys для частых действий

## Приоритет 3 — Полезно

> Дифференциация от конкурентов, расширение возможностей продукта.

### 3.1 API для интеграций
- REST API с авторизацией по токену
- Эндпоинты: получение списка партнёров, броней, статистики
- Webhooks для событий: новая бронь, подтверждение сделки, новая регистрация
- Документация (Swagger/OpenAPI)
- Возможность подключить Profitbase, 1С, BI-системы

### 3.2 Программы лояльности
- Кешбэк партнёру за объём (3% при 5 сделках, 5% при 10 и т.д.)
- Реферальная программа: партнёр приглашает партнёра, получает бонус с его первых сделок
- Сезонные акции с повышенным вознаграждением
- Накопительный рейтинг с периодическим обнулением (квартальные конкурсы)

### 3.3 Обучение внутри приложения
- Короткие видеокурсы по проектам застройщика
- Тесты после каждого модуля
- Сертификаты "Эксперт по ЖК Бруклин" с публикацией в профиле
- Геймификация обучения: XP за пройденные курсы
- Обязательные курсы для доступа к определённым проектам

### 3.4 Чат с менеджером застройщика
- Прямая связь риелтора с конкретным менеджером отдела продаж
- История переписки, прикрепление документов
- Уведомления через Telegram
- Распределение менеджеров по проектам или по партнёрам

### 3.5 Многопроектность (multi-tenant)
- Несколько застройщиков в одной системе
- Изоляция данных между tenant'ами
- Брендирование под каждого: логотип, цвета, домен
- Биллинг по подписке (если продавать как SaaS)
- Шаблоны настроек для быстрого онбординга нового клиента

## Принципы развития продукта

1. **Не пытаться повторить Profitbase.** Развивать то, в чём мы сильнее: мобильность, геймификация, партнёрский фокус.
2. **Каждое улучшение должно повышать одну из метрик:** удержание партнёров, скорость закрытия сделки, доверие застройщика.
3. **Юридическая и операционная зрелость важнее новых фич.** Один инцидент с потерей данных или штрафом Роскомнадзора стоит дороже всех новых функций.
4. **Не строить впрок.** Каждая фича должна решать боль конкретного пользователя — собственника, админа или риелтора.
5. **Сохранять простоту для риелтора.** Это главное преимущество перед Profitbase: открыл, увидел, использовал.
